# Machines 论文 V2 技术定稿：闭环补偿响应条件化的步态选择

日期：2026-10-20。平台：`huxiaoyi-ovo/Pcrnet_hexapod`；本稿不再以 `Grasp_hexapod` 作为实验平台。

## 1. 唯一研究问题与可信贡献边界

给定**同一个实际机身补偿控制器** π_c，在相同导航速度、相同地形通过条件下，候选步态 θ 会改变：

(1) 产生的相机扰动；(2) 当前支撑状态、关节裕度和实际执行器带宽下，π_c 能消除扰动的效果。

目标是由在线可获取的状态预测 **π_c 真正执行后的残余图像运动**，并选择最小者。

贡献 C1：步态条件化的 **扰动—实际闭环补偿响应联合预测**。**不是**宣称首次 CPG、首次姿态控制、首次视觉稳定、首次在线 MPC 调 CPG。这里的“补偿能力”首先是*可观测的闭环衰减表现*，由控制器开/关配对数据辨识；不能将它写成已经精确求出的动力学可行域。

贡献 C2：在**同一实际补偿器**和约束下，以预测的**残余图像运动**进行步态调度，并用原始扰动排序、固定能力预算、历史残余反馈排序等对照分解真实收益。

## 2. 模型应当长成什么样

记 o_t 为在线可获取的当前状态（关节、IMU、当前接触估计、当前深度和局部地形估计），θ 为候选步态，π_c 为固定机身补偿器，\(r^{0}(\theta)\) 与 \(r^{\pi}(\theta)\) 分别为在该步态下补偿关闭和开启后的非期望图像运动；注意正常向前行走的相机视差不算抖动。

- 物理解释：\(d^\theta = F_\psi(o_t,\theta,\hat{\mathcal T})\)；\(r^{\pi,\theta}=G_\eta(o_t,\theta,d^\theta,\pi_c)\)。其中 G 必须体现真实 π_c 响应，不能凭理想瞬时 u_c 求下界。
- **首个可执行版本**：对相同相机指标拟合两个轻量模型 \(\hat J^0(\theta,o_t)\)、\(\hat J^\pi(\theta,o_t)\)，条件特征包含 f、β、步长、触地软化、局部粗糙度、坡度、步态相位、未来规划支撑腿数、关节余量及现时 IMU 角速度。输出为短窗 RMS 非期望图像位移（px/frame）。再单独预测可达的实际行走速度。
- 闭环能力的**诊断量**：\(\widehat{\Delta J}_{\pi}(\theta)=\hat J^{0}(\theta)-\hat J^{\pi}(\theta)\)。其值可以为负，表示补偿器在这一条件下反而恶化了成像；不能强制截为非负。它是*效果指标*，不是方向/频率可行域。
- 后续若有足够真实数据，可扩展到未来 H 步 6D 相机运动和多频带传递响应；论文以已验证的实现为准，不必先实现一个全身动力学 MPC。

在线选择：

\[
 \theta_t^*=\arg\min_{\theta\in\Theta_{\rm safe}}
 \hat J^\pi(\theta,o_t)+\lambda_s\|\theta-\theta_{t-1}\|^2,
 \quad \hat v(\theta,o_t)\ge v_{\min}.
\]

**严格区分**：可行候选筛选（接触/IK/足端离地/关节限速）由真实下层物理模型负责；预测器只负责**候选排序**，不得以预测低抖动代替安全可行性检查。支撑模式的切换与候选相位必须连续。

## 3. 数据闭环：如何真正让模型学到“改步态的后果”

1. 基于 PCR-Net `legged_gym/envs/hex_v4/hex_ground.py` 建立独立的论文任务配置、平地/斜坡/台阶/随机起伏地形。不要直接用 PCR 的目标跟随成功率作为新论文结果。
2. 固定导航速度（并记录实际速度），规划参数化三角步态候选，至少跨越三个步频水平、三个占空比水平及两种触地曲线；样本分布需要覆盖与在线选择器同一候选菜单。
3. 在**相同地形实例、相同目标速度、相同候选参数、相同初始分布**下分别启用/关闭 *同一* Roll/Pitch/Z 补偿器。机器人运动轨迹可能发散；配对是条件配对，不应伪装逐帧完全相同的因果反事实。
4. 每 0.5–1 秒窗口记录：`terrain_instance_id, pair_id, seed, controller_on, θ, phase, measured IMU, commanded/actual speed, planned contact, predicted IK headroom, RGB/静态特征残余抖动`。特征必须在候选执行**之前**可得到，`future measured contact/terrain exact state` 仅能作为离线验证标签，不能进入在线特征。
5. 训练/验证/测试 **按地形实例 + seed 分组**，而不是按视频帧随机拆分；`pair_id` 的开/关数据必须一起分到同一集合。所有候选调参只用训练与验证集。
6. 在测试集分别报告 `raw`、`compensated` 模型 MAE、排序正确率、top-1 regret；排序比较必须在**相同场景状态和候选菜单**上进行，而不是把不一致的样本拼成一个候选集。

现阶段新增 `src/closed_loop_surrogate.py`：纯 NumPy 标准化 Ridge，从这种 CSV 学习两个扰动指标及实际速度预测，提供 `raw` 与 `closed_loop` 两种公平排序接口。代码可执行；**没有训练数据，也没有实证结果**。

## 4. 最有信息增益的实验：不是示意性反转，而是排序全局统计

- 在测试地形所有候选对上统计 `raw` 排名与 `compensated` 排名不一致的比例、增益分布、典型相位与地形，按**独立场景**汇总；不能只展示一个挑选出的反例。
- 与 `Best Fixed + π_c`、`Raw-min + π_c`、`History-only residual + π_c`、`Gait-independent authority + π_c`、`Ours + π_c` 比较；保证候选菜单、速度、低层 π_c、接触约束一致。
- 如果排序反转罕见，也要如实给出总体统计；该机制的提升可能集中在高粗糙度、高负载或接触切换阶段。不能事先保证一定显著。
- 另做“补偿器频响/延迟辨识”——独立测试几种安全幅值的低频 Roll/Pitch/Z 姿态参考，实测闭环相机角速度衰减，区分关节余量够但响应太慢的情况；由此决定用于论文的能力表征维度。
- 图像指标必须剔除平滑导航运动的预期光流；模拟相机位姿导出的 px/frame 为动力学代理指标；独立真实视频静态特征残余光流 / 重投影误差用于验证。曝光设置固定或记录，不把 IMU 模糊代理直接称为真实图像清晰度。
